# 面试题仓库 PRD

## 1. 背景

团队在准备面试题时，内容通常分散在文档、聊天记录、个人笔记和零散代码片段里，导致以下问题：

- 题目难以统一管理，重复录入多。
- 浏览和检索成本高，复用效率低。
- 移动端体验差，查看和复习不方便。
- 内容格式不统一，后续难以沉淀。

本项目目标是建立一个小团队自用的面试题仓库，支持录题、查题、筛选、移动端浏览和基础 AI 辅助。

## 2. 产品目标

### 2.1 业务目标

- 让团队成员能稳定录入和浏览面试题。
- 让题目可被快速搜索、筛选和复用。
- 让题库在 PC、Pad、手机上都可用。
- 让题目的整理和维护成本尽量低。

### 2.2 成功标准

- 团队成员能够在一个系统里完成录题和查题。
- 常见题目可以通过关键词、标签、难度、创建人快速找到。
- 移动端浏览时，默认折叠答案，降低阅读噪音。
- 题库可通过导入/导出进行备份和迁移。

## 3. 产品定位

- 类型：内部自用的面试题仓库。
- 使用对象：管理员和团队成员。
- 公开性：不开放注册，不面向外部公开。
- 角色：admin、member。

## 4. 核心原则

- 先做内容管理和检索，不做复杂社区化能力。
- 优先保证录题、查题、移动端浏览和部署可用。
- AI 只作为辅助工具，不作为主流程依赖。
- 不引入审核流、版本历史和回收站，降低第一版复杂度。

## 4.1 特殊术语替换规则

- 为了掩饰本项目为面试室题库，所以伪装成笔记，项目开发依然是面试题库，只在前端显示层统一替换术语：当界面文本或按钮文案中出现“面试题/题目/题库/答案”等面向用户的汉字时，应使用“笔记/笔记/笔记库/详情”作为替代显示。
- 该替换规则仅作用于前端可见文案；后端 API 名、数据库字段名或代码变量可保持原名以减少兼容改动，但在需要对外文档或 API 返回给终端用户时，优先使用替换后的术语。
- 产品文档（PRD、用户说明）应同步记录该替换规则，确保运维与前端开发统一口径。

## 5. 角色定义

### 5.1 Admin

- 创建和管理账号。
- 管理全站题目。
- 维护基础配置。

### 5.2 Member

- 登录系统。
- 新增、编辑、浏览、筛选题目。
- 使用 AI 辅助生成标签、摘要和难度建议。
- 导出或导入题库数据。

## 6. 内容范围

### 6.1 题目基础字段

- 题目标题。
- 题目内容，支持 Markdown 与图片。
- 答案内容，支持 Markdown 与图片。
- 标签。
- 难度。
- 创建人。
- 可见性：公开 / 私有。
- AI 辅助生成结果：摘要、标签建议、难度建议。
- 每日回想状态（按用户 × 题目维度）：出现次数、完全掌握标记。

### 6.2 不做的内容

- 不做开放注册。
- 不做审核流。
- 不做编辑历史和版本回滚。
- 不做题目社区推荐流。
- 不做后端在线判题服务。
- 不做多语言在线执行器。

## 7. 关键用户场景

### 7.1 管理员创建账号

系统启动时先完成默认管理员账号初始化；管理员登录后，为成员创建账号并发放初始登录信息。

### 7.2 成员录入题目

成员填写题目标题、题干、答案、标签和难度，保存后进入题库。

### 7.3 成员浏览和检索

成员通过关键词、标签、难度、创建人快速定位题目，并在列表中直接展开答案。

### 7.4 成员使用 AI 辅助

成员在录题页主动点击 AI 辅助按钮，系统在弹框中返回摘要、标签建议和难度建议，成员可一键应用建议结果，也可以忽略后继续手动编辑。

### 7.5 数据导出与导入

管理员或成员可以导出题库备份，也可以导入既有题目数据。

## 8. 功能需求

### 8.1 登录与账号管理

- 系统不开放自注册。
- 账号由管理员预创建。
- 系统启动流程包含默认管理员账号初始化。
- 支持用户名或邮箱加密码登录。
- 登录后进入题库首页。
- 管理员可以新增、停用和重置成员账号。

### 8.2 题目管理

- 新增题目。
- 编辑题目。
- 删除题目。
- 设置公开或私有。
- 录题时使用普通文本编辑。
- 题目列表展示核心信息。

### 8.3 题目浏览

- 支持题目列表。
- 默认按搜索结果和筛选结果展示。
- 默认折叠答案。
- 点击按钮可展开或收起答案。
- 支持详情页查看完整内容。

### 8.4 搜索与筛选

- 关键词搜索。
- 按标签筛选。
- 按难度筛选。
- 按创建人筛选。
- 可结合多个筛选条件。

### 8.5 AI 辅助

- 录题页通过按钮触发 AI 分析。
- AI 输出摘要、标签建议和难度建议，并在弹框中展示结果。
- AI 建议支持一键应用到当前题目。
- AI 结果也可忽略，不阻塞保存。
- AI 失败不阻塞保存。

### 8.6 导入导出

- 支持导出题库数据。
- 支持导入题库数据。
- 导出格式优先 JSON，兼容 CSV。
- 导入时要做字段校验和重复提示。

### 8.7 移动端体验

- PC、Pad、手机端自适应。
- 手机端列表为单列卡片。
- 答案默认折叠。
- 使用独立按钮展开答案，避免误触。

## 9. 权限规则

- admin 拥有全量管理权限。
- member 可以浏览全部公开题目和自己有权限看到的私有题目。
- 私有题目默认仅创建者和 admin 可见。
- member 可创建题目。
- member 对自己创建的题目拥有编辑和删除权限。
- admin 可编辑和删除所有题目。

- 启动流程默认初始化管理员账号。

- 默认折叠答案。

## 11. 验收标准

- 管理员可创建账号，成员可登录。
- 成员可创建、编辑、删除题目。
- 成员可按关键词、标签、难度、创建人搜索和筛选。
- 手机端查看题目时答案默认折叠。
- AI 能返回可用的标签、摘要和难度建议。
- 系统可通过 Docker Compose 一键启动。
- 可完成题库导出与导入。

## 12. 风险与约束

- AI 依赖外部服务，需考虑额度和失败重试。
- 文本展示按原文显示换行。
- 导入数据需做格式校验，避免脏数据进入主库。
- 如果后续要加多人协作编辑，当前没有版本历史会增加回滚成本。

## 13. 微信小程序端（Taro）

### 13.1 定位

- 与浏览器版共用同一套后端 API 和数据，是面向移动端的第二种客户端形态。
- 不影响浏览器版：后端仅做增量扩展（微信登录接口、用户模型 openId 字段），现有 Web 功能与部署完全不变。
- 技术形态：Taro 4.x + React + TypeScript，位于 `miniprogram/` 目录，独立构建发布。

### 13.2 登录与账号

- 支持微信一键登录：`wx.login` 获取 code，后端调用 code2session 换取 openid。
- 首次微信登录自动创建成员账号（用户名形如 `wx_xxxxxxxx`），无需管理员预创建。
- 使用已有账号（用户名+密码）登录时自动绑定微信 openid，之后可直接微信一键登录。
- 账号密码登录方式在小程序内继续可用，账号仍由管理员统一创建。
- 服务端未配置微信 AppID/Secret 时，微信登录不可用并给出提示，账号密码登录不受影响。

### 13.3 功能范围

- 笔记中心：搜索、标签/难度/可见性多选筛选（本地缓存记忆）、Markdown 渲染、默认折叠点击展开、下拉刷新、分页加载。
- 笔记维护：新增、编辑、删除；权限与 Web 端一致（管理员可维护所有，成员仅维护自己创建的）。
- AI 辅助：编辑页触发生成摘要、标签建议、难度建议，支持一键应用。
- 标签：标签云浏览、按标签跳转筛选；管理员可新建/编辑/排序/删除标签。
- 系统设置：修改用户名、修改密码、退出登录；管理员可访问用户管理与标签管理。
- 导入导出在小程序端仅提示，实际操作引导至网页端。

### 13.4 验收标准补充

- 微信开发者工具或真机中可完成微信一键登录，并自动创建或绑定账号。
- 小程序内可完成与 Web 端一致的浏览、筛选、录题、编辑、删除流程，数据与 Web 端互通。
- 未配置微信密钥时，小程序可降级使用账号密码登录。

## 14. 每日回想系统（间隔重复学习）

### 14.1 定位

- 独立的学习入口（学习主页/每日回想 tab）：从题库中按权重随机抽题，先自行回忆作答，再对照详情做自评反馈。
- 支持标签/难度筛选偏好，选择持久化在本地，下次进入自动恢复。

### 14.2 抽题与权重规则

- 登录用户抽题按「出现次数」自动降权：出现次数越多权重越低，从未出现过的优先。
- 自动档位与出现次数映射：0 次=优先推荐，1-2 次=常规复习，3-5 次=继续巩固，6+ 次=低频回顾。
- 未登录用户仅抽取公开题目，不记录回想状态。

### 14.3 自评反馈（对照回忆后）

| 选项 | 效果 |
|---|---|
| 没记住 | 出现次数清零，立即回到最优先推送 |
| 模糊 | 出现次数 +1，推送频率基本不变 |
| 记住了 | 出现次数 +2，降低推送频率 |
| 完全掌握 | 标记完全掌握，不再推送 |

- 反馈按钮带悬浮说明，描述对推送频率的影响。
- 未登录用户不显示反馈入口。

### 14.4 完整回想计数规则

- 抽到题不计数；**点击对照回忆自评选项才算一次完整回想**（记录回想日志，用于热力图、累计回想、连续打卡等统计）。
- 同一篇反复调整反馈只计一次，换题后重新计数。

### 14.5 手动档位

- 等级 1-4 支持手动调整：调整会将出现次数重置为对应档位的等效值，并恢复自动调节（后续出现次数继续自动升降档）。
- 等级 0（完全掌握）手动锁定，永不自动调整；「恢复自动调节」选项仅对等级 0 笔记显示。
- 手动标记仅等级 0 显示「手动」徽标。

## 15. 数据看板

### 15.1 内容

- 统计卡：今日回想、累计回想、连续打卡（天）、完全掌握数。
- 回想热力图：GitHub 风格 53 周 × 7 天，悬浮提示显示当日回想次数与日期；四档色阶（0 次 / 1-5 次 / 6-15 次 / 15 次以上），今天固定在最右列。
- 近 7 天回想趋势柱状图（含每日次数与星期标签）。
- 推送频率分布（优先推荐/低频回顾/继续巩固/常规复习/优先推送/未出现过）。
- 薄弱标签 Top 5：按标签聚合自评反馈，薄弱度 =（没记住 + 0.5 × 模糊）/ 反馈总数，仅统计反馈 ≥ 2 次的标签。
- 自评反馈分布（记住了/模糊/没记住/完全掌握次数）。
- 我的笔记：笔记总数、公开/私有、难度分布、高频标签 Top 6、最近回想列表。

### 15.2 布局与交互

- PC/Pad：整页锁定一屏禁止滚动；热力图行高度固定（180px），近 7 天趋势行与我的笔记行按剩余高度弹性分配；手机端恢复自然高度页面滚动。
- 最近回想条目多时在面板内滚动，不撑破容器。

## 16. 图片上传

- 编辑页标题与正文均支持粘贴/拖拽/工具栏选择图片，统一上传至后端。
- 存储方案：MongoDB GridFS（`images` 桶，255KB 分块），Markdown 中保存 `/api/images/<id>` 引用地址。
- 上传限制：仅登录用户，单张 ≤ 10MB，仅 `image/*` 类型。
- 读取：公开访问（`<img>` 标签无法携带 Authorization 头），URL 为随机 ObjectId 不可猜测；浏览器强缓存一年。
- 小程序端：渲染时自动将 `/api/images/...` 相对路径补全为绝对地址（`API_BASE`）。
- 已知边界：暂无孤儿图片清理机制（删除笔记/移除引用后文件仍保留），GC 方案已规划未实现。
